## What LangChain Is

LangChain is an **open-source interface** that simplifies the application development process using LLMs. It provides a structured way to integrate language models into various use cases, including natural language processing (NLP) and data retrieval.

### The full component list

- Documents
- Chains
- Agents
- Language model
- Chat model
- Chat message
- Prompt templates
- Output parsers

This video covers the last five (language model, chat model, chat message, prompt templates, output parsers). Documents, chains, and agents are handled elsewhere in the module.

## Language Models

The language models in LangChain are the foundation — LLMs that take **text input** and generate **text output**, helping complete tasks and summarize documents.

LangChain uses **IBM, OpenAI, Google, and Meta** as primary language model providers.

The worked example generates a response for a new sales approach using IBM watsonx.ai with the **Mixtral 8x7B Instruct** model:

1. Import the necessary dependencies — `GenParams` and `ModelInference` from the IBM Watson Machine Learning package.
2. Customize the model by adjusting settings such as **tokens** and **temperature**.
3. A model object is created.
4. Pass in a prompt; the model returns generated response text.

## Chat Models

A **chat model** is designed for efficient conversations — it understands questions or prompts and responds to them like a human.

The pattern shown: first create a language model using watsonx.ai, then transform it into a chat model using the **`WatsonxLLM`** function, which converts it into a conversational LLM able to engage in dialogue.

The example prompt: *"Who is man's best friend?"*

## Chat Messages

Chat models handle various **chat message** types, which is what makes them effective in a dynamic chat environment:

- **HumanMessage** — user inputs
- **AIMessage** — generated by the model
- **SystemMessage** — instructs the model
- **FunctionMessage** — function call outcomes, with a `name` parameter
- **ToolMessage** — tool interaction results

### The two properties of every chat message

- **Role** — who is speaking
- **Content** — what is being said

The worked example builds a fitness-activity bot:

1. Configure the model's persona using a **SystemMessage** (instructing it to be an AI bot answering "What to eat" in one short sentence).
2. Simulate a past conversation using **HumanMessage** and **AIMessage** pairs.
3. The model then generates responses informed by that previous dialogue.

You can also operate the chat model with **HumanMessage alone** — no system message or AI message cues — in which case the chatbot responds directly to human input without a configured persona or conversation history.

## Prompt Templates

Prompt templates **translate the user's questions or messages into clear instructions** that the language model uses to generate appropriate, coherent responses.

### Types

- **String prompt templates** — for single-string formatting.
- **Chat prompt templates** — for message lists.
- **Message prompt templates** — including `AIMessagePromptTemplate`, `SystemMessagePromptTemplate`, `HumanMessagePromptTemplate`, and `ChatMessagePromptTemplate` (which allows flexible role assignment).
- **MessagesPlaceholder** — provides full control over message rendering.
- **FewShotPromptTemplate** — provides specific examples ("shots") for the LLM.

The chat prompt template example specifies each message's **role** and **content**, and within the content includes **parameter placeholders** for repeated use — so one template generates dynamic, flexible messages based on input parameters. Then you format the prompt.

### Example Selectors

When using few-shot prompting, it matters *which* examples from your example library end up in the prompt. An **example selector** makes that choice efficient.

LangChain's selection strategies:

- **Semantic similarity**
- **Max Marginal Relevance** (for diversity)
- **Length-based** selection for efficient prompts
- **N-gram overlap** (for textual similarity)

The video shows code using an **n-gram overlap example selector** to form a few-shot prompt.

## Output Parsers

**Output parsers** transform an LLM's output into a more suitable format, generating structured data. LangChain provides a library of parsers for various formats: **JSON, XML, CSV, and Pandas DataFrames**.

The worked example uses the **`CommaSeparatedListOutputParser`** to convert an LLM's response into CSV format — structuring the output so it's simple to handle and analyze in spreadsheet applications.

## Recap

- LangChain is an open-source interface that simplifies application development using LLMs.
- Language models take text input and generate text output.
- Chat models understand a question or prompt and respond like a human.
- Chat models handle message types: human, AI, system, function, and tool messages.
- Prompt templates translate questions or messages into clear instructions.
- Example selectors instruct the model about the inserted context and guide the LLM toward the desired output.
- Output parsers transform LLM output into a suitable format.

The **role/content** structure of chat messages is the concept that pays off most later. It's why `SystemMessage` can set a persona that persists across a conversation, and it's the abstraction that model-specific special tokens implement underneath — Module 3's `<|im_start|>system` / `<|im_start|>user` markers are just Qwen's on-the-wire encoding of exactly these roles. Seeing both layers makes it clear that LangChain's message classes are a portable interface over formats that differ per model family.

The distinction between a **language model** and a **chat model** also explains a real detail in the local Ollama labs: the custom `OllamaLLM` class subclasses the plain `LLM` interface (text in, text out), which is why its chains return a bare string rather than an object with `.content` — chat models return message objects, plain LLMs return strings.

**Output parsers** get their full workout in Module 3, where `JsonOutputParser` plus a Pydantic schema turns free-form model output into validated structured data. And **example selectors** are the first appearance of embeddings-based semantic similarity in this certificate — the same mechanism that powers RAG retrieval later in this very module.
